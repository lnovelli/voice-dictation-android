# Floating dictation button: gesture and microphone plan

## Goal and proposed interaction

Make each interaction a single continuous touch: touch down, move or hold, and release. A tap and then a separate swipe is not required. Use the Android long-press timeout; small movement within touch slop before it fires remains a hold. After the haptic, movement repositions the button; releasing without moving does nothing.

| State | Tap/release | Swipe up | Swipe down | Swipe left | Long press, then move |
| --- | --- | --- | --- | --- | --- |
| Idle | Start local dictation | Microphone chooser, editable | Hide for this focused-editor session | No action | Reposition |
| Local recording / starting / capture-limit wait | Stop and transcribe | Read-only microphone panel | Cancel and discard | Cancel and discard | Reposition |
| Local processing / polishing | No action (existing behavior) | Read-only status panel; no microphone is active after capture stops | Cancel and suppress output | Cancel and suppress output | Reposition |
| Externally owned session | Preserve owner-controlled status; no overlay Start/Stop/Cancel | No local microphone chooser for a remote session | No action | No action | Reposition status button |

User confirmed preserving tap-to-stop and cancellation during processing, strict swipe directions, and restricting button positions to leave space for the gestures. Idle left/right swipes remain no-ops and external session ownership is preserved. An unrecognized gesture must never turn into a tap. Do not equate beginning capture, a saved microphone preference, or a request to route with actual microphone capture or routing.

## Implementation

1. **One gesture state machine.** Replace `setupTouchAndDrag()` in `app/src/main/java/com/ludo/voicedictation/overlay/OverlayManager.kt` with states such as pending, swiping, moving and finished. On DOWN snapshot local/external/session identity and available actions; show direction cues immediately. Before the hold timeout, crossing touch slop cancels the long-press timer and enters swipe tracking without moving the button. On timeout, remove swipe cues, perform system-respecting `LONG_PRESS` haptic, enter move mode, and start drag from the touch position at the transition (no jump). Update raw-coordinate deltas with existing clamping and save the portrait/landscape pair at completion or interruption. On UP dispatch at most one action; revalidate state, owner and session so a delayed gesture cannot start, stop, cancel or open a chooser for a different session. Do nothing on touch cancellation or extra pointers apart from cleaning up and saving an already-moved position. Account for orientation change, hide, lock, service destruction, failed window operations, and capture state changes while the finger is down.

2. **Visual action targets and strict directions.** Add compact, clearly distinct microphone, hide and discard icons, with only applicable targets shown while touched and a visible highlight when a target is selected. Keep up/down/left fixed in screen coordinates. Current overlay is only 80 dp square and its window often extends partly off-screen; a cue layer outside the small button window (for example a temporary non-touchable overlay retaining the original touch stream) must not interfere with the underlying editor or shift persisted coordinates. Lay out and hit-test in the same screen coordinates, scale with existing settings, and respect usable display bounds. Revise drag clamping, default placement and restoration of saved portrait/landscape positions so the button always leaves room for the visible up, down and left targets and actual finger movement in those directions; previously edge-hugging positions will shift inward. Recompute on rotation, resize and scale changes. Use generous target/hit areas and a clear cancellation dead zone; lifting on a target executes it, and lifting elsewhere does not accidentally start/stop dictation. Long-press move mode closes targets. Choose compact adaptive dimensions for constrained displays and explicitly handle cases where the screen cannot accommodate the full layout; do not silently remap directions. Exact geometry and thresholds need device tuning.

3. **Field-scoped hide.** Let `DictationAccessibilityService.kt` own a process-local suppression token for the currently eligible focused editor. The idle downward action requests suppression and hides the overlay without calling a cancellation path; every idle show/refresh branch must respect it, including focus-grace callbacks. If the button is hidden while always-visible mode is enabled, immediately disable the persistent always-visible setting; the user must manually re-enable it in Settings. Notify the user that the setting was disabled. Normal focus-driven visibility then applies, with the current field suppressed until a genuinely different eligible editor is detected. Observe actual application input focus and compare privacy-minimal ephemeral node/window identity, not text, hints, selection or cursor, and do not treat clicks, input restarts, repeated events, temporary missing nodes, IME popups, or the chooser itself as proof of a different field. Never use this identity as permission to insert. Preserve existing screen-off, service shutdown, focus grace and external-session status rules; clear ephemeral state on service teardown/process death. If the editor is unavailable or identity is ambiguous, don't falsely claim a different editor. No stored field contents or persistent per-field identifiers.

4. **Read-only current microphone.** The current chooser in `OverlayManager.kt` refuses to open when the engine is busy and highlights the *preference*, not verified routing. Add a session-scoped, thread-safe, generation-guarded route snapshot in `app/src/main/java/com/ludo/voicedictation/asr/SpeechEngine.kt`: obtain `AudioRecord.routedDevice` only after capture has started and delivered a buffer, including the automatic/default case, and update it when Android changes the route; clean it up with the recorder. Map the currently routed device to the displayed list using the live device ID only for the current capture, not as a saved identity. While local capture is active, show a non-editable panel that explicitly marks the verified active device; if not yet verified, unavailable, disconnected, unsupported, or ambiguous, say so instead of guessing or labeling the preference as active. Do not start a recording for discovery. During starting or after capture stops, show the appropriate 'starting / no microphone currently active' status; do not present a stale last route as active. Preserve the idle chooser's stable preferred identity, ambiguity checks, validation at selection, and system-default label. Prevent preference changes throughout local busy states and re-check immediately before a preference write. Refresh/dismiss the panel appropriately on route, state and session changes; keep it non-focusable and dismissible without stealing editor focus. Never control external sessions or imply remote PCM uses this device's microphone.

5. **Accessibility and documentation.** Keep click/tap accessibility behavior; provide discoverable labeled accessibility actions for microphone, hide, cancel and move/reposition where applicable, plus accurate content descriptions and announcements. Ensure an accessibility long-click does not imply the old discard or microphone chooser and has a usable non-gesture alternative for repositioning. Update current instructions/recording-limit cue in `OverlayManager.kt`, `README.md`, and `docs/development/overlay-privacy.md`; preserve historical release notes and unrelated work.

## Focused verification and boundaries

- Run the smallest practical build: `./gradlew :app:assembleDebug --console=plain`. Do not run full suites or device behavior tests by default. A build does not verify actual gesture timing, haptics, audio routes, field identity, screen-edge usability, TalkBack or device behavior.
- If authorized separately, check on an Android device: idle tap/swipes; capture Stop/Cancel; Cancel during starting, cap wait and processing; no accidental tap after movement or held release; drag persistence/orientations; edge/corner targets; focus changes between two fields in one app vs repeats/keyboard restarts; always-visible and inaccessible editors; system default/explicit/route changes/disconnects; dialog dismiss/state transitions; interruption, lock and external ownership; accessibility actions.
- Preserve existing uncommitted changes, notably the audio pipeline and model validation docs. Implement nothing as part of this planning turn.

## Limitations

Focus identity and actual routing are Android/provider-dependent: two editors may not be reliably distinguishable, and `routedDevice` may be unavailable, change or not map to the known list. These limitations must be surfaced, not silently guessed. Screen position will be more constrained than before, particularly at large button scales or on small displays.
