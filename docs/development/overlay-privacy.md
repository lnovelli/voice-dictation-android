# Overlay, focus and privacy

## Visibility versus insertion

`DictationAccessibilityService` reconciles the active application's input focus with accessibility events and, on Android 13+, input-method start/finish callbacks. Those callbacks are an editor-active signal only: do not read editor text, hints, selection, surrounding text or an InputConnection to decide visibility. A focused enabled editable node can show the button even without a session; a noneditable custom editor needs a matching active session and the relevant editor evidence. A matching session with a missing or enabled unfocused node can justify visibility only after active-root/window checks; reject disabled nodes and known competing/IME/system windows. A click triggers reevaluation, not proof of an editor. Debounce focus/window events, defer finish reconciliation briefly, and clear session state on screen-off/interruption/teardown. Same-package sessions cannot prove which window owns the connection, and stale nodes can cause both false positives and negatives. Android or apps may hide overlays; do not claim a workaround.

Visibility is not insertion authority. At local capture start retain only the eligible focused input node in `rootInActiveWindow`, never a stale last-focused fallback. Before delivery refresh it and require it still be the same eligible focused node in the active root window, then recheck before `ACTION_PASTE`. A matching live input session can qualify an enabled focused custom editor; a generic session alone is insufficient. Paste only the transcript, preserving current selection. If no valid original target remains or paste fails, retain/copy the transcript to clipboard with brief feedback, never redirect it to a newly focused field. External IPC and History reprocessing must not use this overlay insertion/clipboard path. Suppress local output on Cancel or lock.

Use overlay permission only where needed, a non-focusable/non-touch-modal `TYPE_APPLICATION_OVERLAY`, and a consistent view-local coordinate space. Short tap finalizes local capture; long hold during capture discards or suppresses pending local output during processing. Distinguish drag with touch slop; a fired hold must latch so release cannot fire again, while CANCEL does not execute. Clean gesture/window state on UP, CANCEL, screen-off, service stop and exceptions. Opening a shade is not by itself cancellation. Preserve position pairs atomically on drag completion/cancellation/teardown, not synchronous writes on every MOVE; keep separate orientation positions and reachable bounds. Configuration preview exists only while resumed. External sessions remain owner-controlled.

For microphone selection, label system default as automatic; store a stable identity rather than transient device port, reject ambiguous/disconnected devices, and verify `getRoutedDevice` only after capture and its first buffer. Preferred routing is a request, not proof; do not start a recording just to discover the default.

## Opt-in diagnostics

Keep visibility diagnostics observational, process-local, explicitly enabled and bounded in time and size. Record decision transitions, trigger, relevant focus/session facts, app-requested/attached view state, insertion outcomes and errors, not field contents, hints, selections or transcripts. Requested/attached visibility does not prove pixels were displayed. Coalesce only adjacent identical decisions with count, time range and trigger totals; explain that intermediate order is lost. Preserve a starting snapshot on clear, and avoid repeated attach failures evicting useful history. Package names and metadata may be sensitive; Android visibility can prevent verification. An `unavailable` package is not proof of absence or mismatch.

Only explicit per-session consent permits syntax-limited provider package-like strings, labeled unverified and potentially sensitive. Capture consent and producer generation together under a lock, and require the same active generation at commit. Stop, restart and clear invalidate in-flight producers; keep expiry token independent of clear so the original deadline still fires. Copy/share only on user action. Test disabled/enabled consent, invalid strings, blocked producers crossing restart/clear and expiry after clear; host stubs cannot establish actual accessibility or device behavior.
