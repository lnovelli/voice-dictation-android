# Architecture, ownership and IPC

## Boundaries

`SpeechEngine` owns shared capture, native recognizers and session lifecycle. `DictationAccessibilityService` and `OverlayManager` provide local floating controls and insertion; `DictationControlService` is the protected external Messenger entry point; `ModelInfo`/`ModelManager` select and install models; History and text transforms are separate. Before refactoring, inventory local capture, live/file IPC, History, preferences, cancellation, model selection, permissions and lock/screen lifecycle. Preserve behavior at each ingress and agree on contract changes before editing shared code.

The local owner exclusively controls local Stop/Cancel; external sessions belong to their authenticated IPC owner. Overlay status observes both and must never acquire or control external ownership. Publish ordered, session-guarded transitions on Main; clear stale indicators on stop, cancellation, cap and cleanup. External recording/processing may keep status visible across focus changes only while the service and overlay permission are enabled and the screen is interactive and unlocked. Lock-screen suppression remains intact.

## Hermes contract

[External dictation IPC](../external-dictation.md) is the repository's canonical detailed protocol, including file format, message envelopes and lifecycle; its release-specific descriptions are historical. When in doubt reconcile it with `AndroidManifest.xml`, `integration/DictationControlService.kt` and `SpeechEngine.kt`. No companion checkout or deployed version is assumed. Coordinate protocol or duration changes with the actual client separately; do not silently invent server changes.

Current provider source defines signature-protected explicit service binding and checks *each* Messenger command's `Message.sendingUid`: exactly one UID package, `com.hermes.assistant`, a matching signature and the granted `com.ludo.voicedictation.permission.CONTROL_DICTATION`. A Bundle package claim is not identity. Reject missing/ambiguous identity or callbacks; never replace the service with an unprotected broadcast or public intent. Commands use protocol 1 and a canonical UUID: START=1, STOP=2, CANCEL=3, completed-file=4, remote PCM start=5 and finish=6; events STATE=101, PARTIAL=102 (remote PCM only), RESULT=103, ERROR=104. STOP/CANCEL/FINISH must match the initiating UID, exact session ID and callback Binder identity. Busy requests do not preempt a local or external owner. Binder death, callback failure, unbind, service teardown, timeout or Cancel suppress output; retain ownership until any in-flight JNI work and cleanup finish. CANCEL has no final acknowledgement. Only RESULT is authoritative; never paste or copy external/History output via the overlay.

Completed-file IPC accepts a readable regular-file descriptor containing nonempty, even-sized raw mono PCM16LE at 16 kHz, at most 120 seconds; reject malformed metadata, size changes, pipes and other nonregular inputs. Read from offset zero, off Main, and close the transferred descriptor on every path including rejected commands and cancellation. It does not open the microphone or require overlay/accessibility permissions. Live START requires a visible, microphone-authorized client binding with capability propagation on supported Android and provider microphone permission; service enabled and model ready apply to both. The client must authenticate each callback's `Message.sendingUid` against the verified provider UID and filter by owner/session/protocol; a transient notification shade is not itself cancellation. Actual backgrounding and cancellation follow the current client lifecycle contract. Client-side account, lock, review and submission fences are the client's responsibility and must be checked in its own current implementation; a public intent is not capture authority.

Wear offload may arrive as a completed file or a separate owner-bound live PCM pipe. The latter requires a selected ready Nemotron model and independently validates EOF, explicit FINISH, count and digest before final flush; it never opens the microphone. It may send bounded, throttled and coalesced unvalidated PARTIAL previews to the owner while input streams, but never a RESULT before explicit Stop and complete validation. Pairing, authenticated transfer, client-side digest/count validation, session/account identity and unsent-draft review belong to the client, not this provider. Do not claim non-streaming models are live. Named-session resolution, pause/review and safe unsent-draft recovery similarly belong to the client; do not infer them from provider RESULT. Their current implementation and device behavior were not inspected here.

The provider currently bounds live capture to 10 minutes and the entire accepted IPC session to 15 minutes; capture-cap wait still needs explicit Stop/Cancel. Preserve finalization margin and inspect the client's independent timeout before changing either bound: increasing only one does not extend end-to-end recording. RESULT follows final processing and cleanup, not merely STOP. Runtime Binder identity, device permission propagation and client behavior are not established by this source inspection.
