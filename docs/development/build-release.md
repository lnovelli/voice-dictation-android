# Build, verification and release

Inspect live Git status and preserve unrelated edits. Current build configuration is in `app/build.gradle.kts` and the manifest; do not infer the current version from historical README release sections. The project packages ARM64 only and uses the bundled sherpa AAR. A focused app build is `./gradlew :app:assembleDebug --console=plain`. If a Kotlin daemon stalls, use `--no-daemon --max-workers=2 -Pkotlin.compiler.execution.strategy=in-process`; use `--offline` only if dependencies are cached. Do not kill unrelated daemons.

By default prefer focused compilation and static/protocol checks. Do not run unit tests, lengthy suites, lint, emulators or real-device behavioral probes unless requested (lint/emulator may be appropriate when materially necessary). Real on-device tests require explicit authorization even for security/correctness risks; install authorization alone permits only minimal install read-back. Builds, host fakes, APK metadata and native host inference do not prove microphone, Binder identity, focus, lifecycle, recognition quality, UI or device performance. State what was actually tested and the gaps.

For an explicitly requested release, read the generic `android-release-automation` skill. The app-specific profile is `.hermes/release/voice-dictation.json` and the plan template is `.hermes/release/voice-dictation.plan.json`; they contain private local configuration and must remain ignored and owner-only. Revalidate their values against current source and release state. Inspect current branch, tags, release assets and version metadata rather than relying on remembered deployment paths. Check intended source and version, package ID and ARM64 ABI. Verify the final named APK with `aapt` and `apksigner`; compare its certificate fingerprint to the intended previous/installed APK. Current releases historically use Android Debug signing: verify configured signer and APK-to-APK continuity without inspecting, requesting or copying keystores or backups. After final copy/rename recheck metadata, SHA-256 and exact artifact readability. Preserve user-configured update URLs and manual-only checks; never embed tokens or credentials.

The GitHub updater contract uses `voice-dictation.apk` and `voice-dictation-version.json`: check current code and assets, tag/version and exact version-tagged URL, version code and final APK digest. Build first; if inputs change rebuild and refresh digest. For an authorized publication, verify intended branch/tag and write access, prepare a draft and read back complete APK and metadata with matching hashes before publication; then verify the public latest release and complete downloads. For any live file target, create verified restrictive rollback copies, stage both files on the same filesystem and atomically replace APK first, manifest second; read back exact targets and public downloads. Do not replay an uncertain or already completed publication step without inspecting live state. Report publication, installation and device behavioral validation separately.

The updater must validate allowed HTTPS URLs/redirects, bounded downloads, manifest digest, newer version, package ID and installed signer before offering the system installer. Opening the installer is not proof of installation. When deployment is explicitly authorized, identify the exact target and signer before `adb install -r`, preserve data, and verify installed version and APK hash; do not uninstall as an update shortcut. Device interaction beyond install read-back needs explicit authorization.
