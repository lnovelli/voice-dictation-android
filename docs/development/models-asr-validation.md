# Model installation and ASR validation

## Model catalog and safe extraction

Inspect `ModelInfo`, `ModelManager`, preferences, Settings, readiness/delete and all live, file and History dispatch paths together. Route by the selected model's capability, not a global streaming switch. Initialize before capture or buffer all audio while loading. Check the exact release asset name, size, contents and digest against the authoritative release listing; validate user-supplied names literally, never silently repair them. Distinguish multilingual Nemotron 3.5, older English Nemotron and Parakeet Unified.

Current `ModelManager` stages downloads in unique app-private directories and verifies a SHA-256 when specified by the catalog; not all existing models have a pinned digest. Do not silently add checksum requirements to unrelated downloads. Admit exactly the four expected filenames under the model root, ignore other entries without resolving their paths, and reject duplicates, missing entries, malformed headers and non-regular file types. Commons Compress `isFile()` is insufficient: require `TarConstants.LF_NORMAL` or `LF_OLDNORM` explicitly. Verify staged files before install; preserve existing model directories including partial ones, restore on failed swap where possible, and clean staging on failure/cancellation. Do not delete older user models as a selection migration. Removing a catalog entry may orphan files: identify them and offer an authorized cleanup path, not silent deletion. Model storage is under app-private `filesDir/models`; do not assume ordinary file managers can access it.

Exercise the actual extractor with the real matching archive and traversal, duplicate, symlink, bad header and missing-entry fixtures, checksum failure and cleanup as well as success. These are targeted checks when the relevant work warrants them, not a claim that they were run here.

## TDT dither and retry

Inspect the exact bundled AAR and matching native source. For sherpa-onnx 1.13.8, NeMo's subclass shadows `config_`: inherited `SetConfig` does not change the copy used by `CreateStream`, so changing feature dither requires recreating the recognizer. JNI dither reaches offline native fbank; pinned kaldi-native-fbank 1.22.3 applies Gaussian noise independently per extracted frame before pre-emphasis/windowing, not once to original PCM. PCM-noise approximation is not identical for overlapping frames.

Current policy retries an empty offline TDT decode once with dither 0.001 if the expanded input fits; streaming and nonempty output are excluded. Normally use up to 100 ms original context on both sides with zero fill at recording edges and no outer silence. For intentionally trimmed VAD chunks, do not reintroduce the removed right tail: use available left context only, no artificial padding. Initial and retry inputs need separate validation. Always-dither is an explicit experimental setting, default off. Retries can duplicate words or hallucinate and cannot recover speech removed by VAD or omissions from nonempty results. Recreation may cause two expensive model loads per empty chunk, backlog or memory pressure; preserve configuration, cancellation, serialized ownership and zero-dither restoration. A failed restoration must not leave a cached broken recognizer.

For a focused retry change, compile/run the actual Kotlin policy with synthetic PCM and callback fakes: empty/nonempty, streaming exclusion, one retry, exact context/padding, size limit, cancellation, failure and next zero-dither decode. If Android JNI cannot run locally, a scratch harness may extract the actual orchestration methods verbatim with fake recognizer/stream types: test biased/unbiased configuration, preservation of every non-dither field, peak live recognizers and failure restoration. Separately inspect actual synchronization/call sites and compile the app; extraction does not establish real JNI, locking or device behavior.

## Streaming and accuracy evidence

Verify the packaged AAR and matching native version before claiming compatibility. In 1.13.8, online Java streams expose `setOption`; NeMo derives feature dimensions from the encoder and unset language selects automatic detection. The multilingual exporter uses 128 features; a generic log from an older English CLI does not prove effective dimension. Keep endpoint resets disabled when Stop is user-controlled. Compare finalization padding against a longer control on multiple shifts of the same real speech and silence. A past host experiment's 1.28 s tail matched a 2.4 s control at three shifts of one English sample, not proof of universal flush or Android performance.

Use identical PCM, actual matching model/runtime, 16 kHz/128-dimensional features and explicit thread caps for comparisons. Include real public speech with references, silence, seeded noise, known blank cases if available and multiple dither streams; hash input and report actual transcript, word errors, hallucinations and runtime. Host inference is not phone lifecycle or performance validation. Nonempty/tag-free output proves execution only. Avoid claiming audio omitted by decoding was recovered by a text-only polisher.

For vocabulary work compare greedy, unbiased beam and bias on/off on the same human-reference targets and negatives, near-homophones, silence, noise, pauses and continuous speech; label synthetic/TTS samples honestly. `max_active_paths` is beam width, `hotwords_score` is reward, not vice versa. Vary dictionary composition as well as score: reward can cause repeats or change unrelated speech, and biased token scores are not reliable acoustic confidence. Verify model/binding supports a real confidence or N-best gate before designing one. Keep bias experimental and default-off; do not use text deduplication to conceal decoder failures.

For dropped words trace saved PCM length, endpoint range, windows and coverage, raw ASR, deterministic transforms, optional polishing and final insertion/IPC, keeping private content out of logs. Compare isolated versus contextual speech and relative volume on the same recording; token starts are not word ends, and isolated retry may hallucinate or duplicate. Never blindly merge. History windows are contiguous but low-energy cuts are not guaranteed word boundaries. Preserve the original audio and report whether diagnostics, target-device behavior and recognition improvements were actually verified.
